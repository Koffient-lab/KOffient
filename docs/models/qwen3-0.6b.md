# Qwen3-0.6B — лёгкая модель MVP

| | |
|---|---|
| Исходник | `Qwen/Qwen3-0.6B`, ревизия `c1899de289a04d12100db370d81485cdf75e47ca` |
| Лицензия | Apache-2.0 (файл лицензии из репозитория) |
| Архитектура | декодер, 28 слоёв внимания, ширина 1024, словарь 151 936 токенов (таблица связана с выходным слоем) |
| Файл | `qwen3-0.6b-tied-q4_k_m-tied.gguf`, 396 705 056 байт, 5,2 бита на параметр |
| sha256 | `7771b2cc9e84b173ad853efc499a822e115a3d3f288b552307f5e9dcac31cb41` |
| Рецепт | конвертация штатным скриптом llama.cpp `b12199` → удаление дублирующего выходного слоя → `llama-quantize` `Q4_K_M` |

**Почему «tied».** В исходном чекпойнте рядом со связанной таблицей словаря лежит отдельный `lm_head`,
побайтно ей равный, и конвертер переносит его в файл: таблица хранится дважды. Мы убираем копию, и движок
использует одну таблицу для входа и выхода. В fp16 модель от этого не меняется: против исходного fp16 самый
вероятный токен совпадает в 100%, KL ≈ 0 (−0,000014, погрешность расчёта), perplexity совпадает до последнего
знака (19,6013; цифры из вывода `llama-perplexity` — запись прогона с ними сохранилась как неудачная из-за
ошибки разбора отрицательного KL, исправленной позже). После квантования есть одно отличие: общая таблица
хранится в Q6_K (как выходной слой), а не в Q4_K, как входная таблица в исходном файле; близость к fp16 от
этого чуть лучше (KL 0,106 → 0,103). Файл `q4_k_m` — 397 МБ вместо 484.

Близость к исходному fp16: KL 0,103 (англ.) / 0,112 (рус.), самый вероятный токен совпадает в 83% / 83%.
MMLU у этой модели на уровне угадывания (0,25 при четырёх вариантах), по ней варианты не сравниваются.
Попарно против исходного `q4_k_m` значимо отличается только русская MMLU (10 хуже / 2 лучше, p = 0,04) —
задача, которая у этой модели вариантов не различает. В инструкциях на английском обрывов по лимиту длины
30 из 300. Функцию без нужды модель вызывает в 8% таких случаев (Granite — в 28–37%).

## Скорость и память

Эмулятор Android x86_64, 4 потока, загрузка без отображения файла, контекст 2048, 3 круга, медиана
(не телефонные цифры):

| | |
|---|---|
| Генерация | 87 ток/с (по кругам 84–106) |
| Обработка промпта, 1024 токена | 500 ток/с |
| Первый токен, вопрос 277 токенов | 0,5 с |
| Первый токен, запрос с шестью функциями, 1274 токена | 2,9 с |
| Пик памяти | 0,70–0,72 ГБ |

Кэш внимания — 112 КБ на токен (fp16, больше, чем у Granite): при контексте 4096, который рекомендует
манифест, памяти нужно примерно на 0,22 ГБ больше (расчёт).

## Как запускать

Общие требования к движку — [sdk-runtime-requirements.md](sdk-runtime-requirements.md). Особенности модели:

- **Режим рассуждений выключать**: в шаблон чата передавать `enable_thinking: false`. Качество измерено в
  режиме без рассуждений; с рассуждениями модель пишет длинное размышление перед ответом.
- **Вызов функций** — модель отвечает `<tool_call>{"name": ..., "arguments": {...}}</tool_call>`.

## Что не проверено

- Работа на настоящем телефоне.
- Качество свободного диалога (оценка судьёй-моделью).
