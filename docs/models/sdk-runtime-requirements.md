# Требования к мосту Kotlin → llama.cpp со стороны модели

Документ для того, кто пишет нативный мост SDK. Основа — наши замеры (как они сделаны —
[METHODOLOGY.md](METHODOLOGY.md)); где утверждение — вывод или оценка, а не замер, это сказано прямо.

Модель MVP — IBM Granite-4.0-1B `q4_k_m` (1024 МБ). Запасная — Qwen3-0.6B `q4_k_m` (397 МБ). Пакеты
моделей (файл GGUF, `LICENSE`, `manifest.json`) в git не хранятся — файлы слишком большие; они собираются
командой `model package` и передаются отдельно.
Манифест — наше предложение формата; если у SDK будет свой формат, перенесём поля в него.

Движок: llama.cpp `b12199` (коммит `372dc5c`). На другой версии цифры ниже не проверялись.

## Обязательно

### 1. Загружать модель без отображения файла в память

```c
struct llama_model_params mp = llama_model_default_params();
mp.load_mode = LLAMA_LOAD_MODE_NONE;
```

По умолчанию (`LLAMA_LOAD_MODE_AUTO`) файл отображается в память; llama.cpp перекладывает веса в формат
для быстрых инструкций процессора и держит эту копию рядом со страницами файла — модель лежит в памяти
дважды. Пик памяти процесса без отображения (эмулятор): Granite 1950 → 1258 МБ; Qwen3 (исходный файл
484 МБ) 1004 → 790 МБ, поставляемый файл Qwen3 без отображения — 703 МБ. Скорость генерации та же. Тёплая
загрузка медленнее на 0,03–0,12 с, холодная — быстрее на 0,2–0,3 с.

Оговорка: страницы отображённого файла система может вытеснить при нехватке памяти, так что пик процесса с
отображением завышает реальную нагрузку. Но перепакованная копия весов — обычная память, и при отображении
она добавляется к файлу. На телефонах с ARM перепаковывается почти всё, выигрыш, вероятно, ещё больше
(не измерено).

### 2. Собирать движок без `i8mm`

```
-DGGML_CPU_ARM_ARCH=armv8.2-a+dotprod+fp16
```

Сборка с `+i8mm` содержит инструкции `smmla`, которых нет, например, у Snapdragon 870 (OnePlus 9R, ядра
Cortex-A77): на таком процессоре она упадёт с SIGILL (вывод по составу инструкций в собранной библиотеке; на
телефоне не запускали). Сборка `armv8.2-a+dotprod+fp16` таких инструкций не содержит. `dotprod` есть почти
у всех телефонов с 2018 года. Позже можно
перейти на несколько вариантов в одной сборке: `-DGGML_BACKEND_DL=ON -DGGML_CPU_ALL_VARIANTS=ON`.

### 3. Задавать все параметры генерации явно

Конвертер записывает в GGUF умолчания генерации производителя (`general.sampling.*`, например штраф за
повторы 1,1 у Qwen2.5), и llama.cpp применяет их, если параметр не задан. Мы измеряли качество при
жадной генерации без штрафов. Чтобы в приложении модель вела себя как на наших замерах:

| Параметр | Значение |
|---|---|
| temperature | 0 (жадный выбор) |
| repeat_penalty | 1.0 |
| presence_penalty, frequency_penalty | 0.0 |
| dry_multiplier | 0.0 |

В цепочке сэмплера llama.cpp это: штрафы не добавлять, `llama_sampler_init_greedy()`.

### 4. Шаблон чата брать из GGUF и разбирать вызовы функций по формату модели

Шаблон лежит в метаданных `tokenizer.chat_template` (Jinja). Вызов функций:

| Модель | Формат ответа с вызовом |
|---|---|
| Granite-4.0-1B | `<tool_call>{"name": ..., "arguments": {...}}</tool_call>` |
| Qwen3-0.6B | `<tool_call>{"name": ..., "arguments": {...}}</tool_call>`; режим рассуждений выключать (`enable_thinking: false` в шаблоне) |

Ответ, который не разбирается как вызов, — ошибка модели, а не моста; на наших наборах у Granite и Qwen3
таких ответов 0.

Разобранный вызов перед выполнением проверять: где функцию вызывать не нужно, Granite всё равно вызывает
её в 28–37% случаев, Qwen3 — в 8%.

### 5. Кэшировать состояние постоянного начала промпта (для Granite — обязательно)

Системный промпт и описание функций одинаковы во всех запросах. Их KV-состояние можно посчитать один
раз и сохранить: `llama_state_seq_save_file` / `llama_state_seq_load_file`. Тогда на каждый запрос
обрабатывается только вопрос пользователя. Запрос с описанием шести функций — 1252 токена у Granite и
1274 у Qwen3; в эмуляторе до первого токена у Granite 7,2 с, у Qwen3 2,9 с (замер). Телефон, вероятно,
медленнее эмулятора, так что без кэша Granite может заставить пользователя ждать десятки секунд (оценка, на
телефоне не измерено; выигрыш от кэша тоже рассчитан, а не измерен).

## Сильно желательно

### 6. Не держать лишний контекст

Кэш внимания выделяется сразу на весь `n_ctx` (fp16): у Granite 80 КБ на токен (320 МБ на 4096 токенов),
у Qwen3 — 112 КБ (448 МБ на 4096). Пик памяти ниже измерен при `n_ctx` 2048; манифесты рекомендуют 4096 —
это по расчёту ещё +160 МБ у Granite и +224 МБ у Qwen3. Ставить `n_ctx` по реальной нужде. Квантование кэша (`type_k = type_v = GGML_TYPE_Q8_0`)
уменьшает его вдвое; потребует flash attention, качество на нашей модели не проверено.

### 7. Потоки — только большие ядра

Генерация на телефоне упирается в пропускную способность памяти, поэтому много потоков ей не нужно, а
малые ядра тормозят общий пул (по опубликованным замерам; сами мы число потоков не подбирали). В C API
`llama_context_default_params()` ставит `n_threads = 4` независимо от устройства (консольные утилиты
llama.cpp берут все ядра). Выставлять `n_threads` по числу больших ядер (частоты в
`/sys/devices/system/cpu/cpu*/cpufreq/cpuinfo_max_freq`) и проверить на телефоне.

## Чего не делать

- Не переквантовывать Granite в Q4_1 и не запускать в fp16: модель выдаёт мусор или NaN (вероятно,
  активации выходят за предел fp16; не доказано). Q5_1 не проверяли.
- Не включать у `llama-server` кэш промптов и контрольные точки состояния для гибридных моделей
  (LFM2): восстановление состояния портило ответы. Для Granite и Qwen3 неважно — у них только внимание
  (на Qwen2.5 проверено: ответы с кэшами и без побайтно одинаковы).

## Что известно о скорости

Цифры эмулятора (x86, не телефон; 3 круга, медиана), загрузка без отображения файла, `n_ctx` 2048:

| | Granite-4.0-1B `q4_k_m` | Qwen3-0.6B `q4_k_m-tied` |
|---|---|---|
| Генерация | 36 ток/с | 87 ток/с |
| Обработка промпта (1024 токена) | 181 ток/с | 500 ток/с |
| Первый токен, короткий вопрос (272 / 277 токенов) | 1,4 с | 0,5 с |
| Первый токен, запрос с функциями (1252 / 1274 токена) | 7,2 с | 2,9 с |
| Пик памяти | 1,26–1,28 ГБ | 0,70–0,72 ГБ |

На телефоне будет медленнее; замер на OnePlus 9R — когда будет доступ к телефону.
